# 界面交互体检报告

> 目标：`app/web/index.html`（单文件前端）+ FastAPI 后端。
> 问题不是"接口通不通"，而是"**用户点下去会发生什么**"。
> 复现环境：Windows · Edge（headless）· 后端 `127.0.0.1:8137` · 离线档
> `FT_AGENT_LLM=off FT_LLM=off FT_WARM_LLM=off FT_NOTIFY_LLM=off`。
>
> 内容分五轮：
> **一～四** 交互 bug 体检（6 个真 bug）；**五～六** 复现方式与静态护栏；
> **七** 排程页改版（视口内自洽布局，含一个花了最久的 CSS 选择器撞车）；
> **八** 播放条排版（控件换皮 + 行高统一）；
> **九** 视图切换按钮（可读性 + 尺寸）；
> **十** 残留诚实清单。

## 一、为什么要分两层体检

| 层 | 工具 | 能看见 | 看不见 |
|---|---|---|---|
| 逻辑层 | `scripts/ui_probe.mjs`（jsdom） | 选择器对不对、字段名对不对、事件绑没绑上、点了有没有反应、有没有 JS 异常 | **排版**：jsdom 没有布局引擎，元素被压成 0 宽、文字被裁切、面板重叠，它一律看不见 |
| 排版层 | `scripts/ui_layout_probe.mjs`（真 Edge + CDP） | 真实盒模型：宽度/高度、溢出、裁切、重叠、可视性 | — |

两层都是**零第三方依赖**：

- jsdom 装在受管 Node 工作区（`C:\Users\<你>\.workbuddy-ai\binaries\node\workspace`），
  脚本用 `createRequire` 显式指根 —— ESM 的 `import "jsdom"` **不认 `NODE_PATH`**，
  这是第一次跑不起来的原因。
- 排版层直接用系统自带的 Edge，CDP 手搓（**Node 22 内置 `WebSocket`**，不需要 `ws` 包）。
  `agent-browser` 没装，而为一个静态页拉 500MB Chromium 不划算。

> **为什么值得分两层**：本轮 6 个真 bug 里，有 3 个只有一层能看见。
> `onEventChange` 未定义是逻辑层的；甘特条越界是排版层的；
> 而"AI 排菜后已选恒为 0 道"两层都看不见 —— 它需要**模拟真实操作序列**
> （点菜 → 筛选 → 一句话排菜）才会暴露。

## 二、发现并修复的问题（6 个）

### B1 · AI 一句话排菜后「已选」恒为 0 道 🔴 高

**现象**：输入"两荤一素快点"→ 甘特图、指标卡、通知全都正常画出来了，但左下角
「已选」还是 `0道`、药丸区还是「未选菜」。**更糟的是紧接着点「应用重排」会弹
"先生成一次排程"** —— 计划明明就在屏幕上。

**根因**（两处叠加）：

```js
// 旧代码
document.querySelectorAll('#recipeList .item').forEach(el=>{
  if(d.picked.includes(el.dataset.name||el.textContent.trim().slice(0,8)))el.click();
});
```

1. 菜谱行模板里**根本没有 `data-name`**，`el.dataset.name` 恒为 `undefined`；
   退回 `textContent.trim().slice(0,8)` 拿到的是 `"鸡翅包饭烤箱烤1"` 这种
   "菜名+分类简称+步数"的拼接前缀，**永远不等于纯菜名**（实测 3 道菜全不匹配）。
2. 列表只渲染前 80 行，识别到的菜若不在窗口内也点不到。

**修复**：不再靠 DOM 点击，直接按识别结果落选中状态（与 `toggle()` 同一套上限/去重规则），
并给行模板补上 `data-name`：

```js
clearSel();
d.picked.slice(0,5).forEach(n=>{
  if(selected.some(s=>s.id===n))return;
  const x=allRecipes.find(y=>y.id===n)||META.find(y=>y.name===n);
  selected.push(x?{...x,id:n}:{id:n,name:n});   // id 一律规范成菜名
});
loadRecipes();updSel();
```

> ⚠️ 修复过程中还踩了自己一个坑：`META` 里的原始对象**没有 `id` 字段**，
> 第一版写成 `selected.push(x||{id:n,name:n})`，去重 `s.id===n` 就永远匹配不上，
> 筛选状态下选 3 道只会留下 2 道。**这个坑是探针自己抓出来的**（见 §三）。

### B2 · 改「动态事件」下拉每次都抛 ReferenceError 🟠 中

**现象**：切换「插单 / 设备故障」下拉，控制台每次一条
`ReferenceError: onEventChange is not defined`。

**根因**：`<select onchange="onEventChange()">` —— **只有调用点，没有定义**。

**修复**：补上定义，并让它做一件本来就该做的事 —— 切事件类型时清掉上一次的重排摘要，
否则会留着"插单「X」…"这种与当前选择不符的旧文案，看起来像已经按新事件重排过了。

> 探针第一次**没抓到**这个 bug：旧写法把 `jsErrors.length = 0` 放在触发 `change`
> **之后**，等于把刚抛的错当场擦掉。改成"先清空再触发"之后立刻现形（§三）。

### B3 · 未生成排程时拖时间轴/点播放 → TypeError 🟠 中

**现象**：进「智能烹饪排程」页（还没点生成），拖一下时间轴或点「▶ 播放」，
控制台 `TypeError: Cannot read properties of null (reading 'tasks')`；
播放态下**每 120ms 抛一次**，控制台刷屏。

**根因**：时间轴和播放按钮在「计划」视图里**始终可见**，用户完全可以"先拖再排"。
而 `seekT()` 直接读 `LAST_PLAN.tasks`，此时 `LAST_PLAN` 是 `null`。

**修复**：`seekT()` 里先更新标签（给用户即时反馈）再早退：

```js
document.getElementById('tLabel').textContent='t='+Math.round(v)+'分';
if(!LAST_PLAN)return;
```

### B4 · 甘特条被顶出轨道右边界 🟡 低（但纯排版 bug）

**现象**：37 条甘特条里 3 条越出泳道右边，最多 16px。

**根因**（两个因素叠加，缺一不可）：

```js
const l=t.start_min/MAX*100, w=Math.max(t.duration_min/MAX*100,3);
```

1. 3% 的最小宽度是为了让极短任务看得见 —— 但末端任务 `left≈99.3%` 再给 3%，
   直接顶出轨道。
2. 更隐蔽的一层：全局是 `box-sizing:border-box`，而 `.sbar` 自带 `padding:0 8px`。
   极短任务算出来只有 **5px**，浏览器会把 border-box 宽度**兜底抬到内边距之和
   （16px）**，于是又越界一截。

**修复**：① 宽度再夹一次剩余空间；② **把内边距挪到内部 `<span>` 上**，
让条自身能缩到任意窄：

```js
const w=Math.min(Math.max(t.duration_min/MAX*100,3), Math.max(100-l,0.5));
```
```css
.sbar{...;padding:0}                    /* 不能再有内边距，否则 5px 被抬成 16px */
.sbar>span{min-width:0;padding:0 7px;overflow:hidden;text-overflow:ellipsis}
```

结果：越界 **0/37**。

### B5 · 甘特条文字从字中间硬切 🟡 低

**现象**：窄条上的 `苹果芒果派·1` 被从字中间切断，变成一块残字。

**根因**：`.sbar` 有 `overflow:hidden` 但**没有省略号**。而且 `.sbar` 是 flex 容器，
`text-overflow` 加在它自己身上**不生效** —— 必须给内部的块级子元素。

**修复**：包一层 `<span>` 并加 `text-overflow:ellipsis`（配合已有的 `title` 提示，
完整信息仍然可得）。

### B6 · 控制台 404：/favicon.ico 🟢 极低

**修复**：内联一个 data-URI favicon，浏览器不再去要 `/favicon.ico`。

## 三、探针自身的两个 bug（值得记下来）

体检工具本身出错比被测代码出错更危险 —— 它会给出**假绿**。

1. **陈旧 DOM 造成假通过**。第 2 节"菜单导航"已经把全部视图都点过一遍（当时 7 个，现 5 个），
   第 9 节再进「排程记录」时 `#histCount` 里留着上一轮的 `0条`，
   等待条件 `includes('条')` **立刻命中**，新请求还没回来就断言了 ——
   于是"历史记录 0 条"这个**假失败**挂了一轮。修复：断言前先清空容器，
   强制等真实渲染。第 6/7/8 节同理（不清空的话 `length>0` 会被陈旧内容满足，
   新请求失败也测不出来）。
2. **错误被自己擦掉**。见 B2。

**教训**：等待条件必须**依赖新渲染的内容**，不能依赖"当前 DOM 里有没有符合的东西"。
另外，把 `jsErrors` 的清零点放在触发**之前**。

## 四、一个"看着像 bug、其实不是"的案例

`.float-input` 里的发送按钮写的是 `class="btn"`，而**样式表里根本没有 `.btn` 规则**
（只有 `.btn-arrow`）。按 CSS 推导，它会落到 `button{width:100%}` 上，
在 `display:flex` 的行里把输入框挤成 **0 宽** —— 看起来是个"悬浮助手没法打字"的严重 bug。

**实测（真 Edge）**：输入框 `194px`、按钮 `132px`、面板 `360px`，**间距 8px，完全正常**。

原因是输入框 `flex:1 1 0%` 时带 `min-width:auto`，它的 min-content 宽度（≈194px）
成了下限，按钮只能吸收收缩量。**布局是"侥幸成立"的，不是设计成立的。**

结论：`class="btn"` 是个**死类名**，当前无害，但它是**脆弱**的 —— 谁给 `.btn` 加一条
`width` 规则就可能把输入框挤没。本次**不改**（改 CSS 有回归风险且视觉零收益），
只在这里记录。**这正是必须用真内核量一遍的理由**：光读 CSS 我会得出错误结论。

## 六、静态护栏（`tests/test_web_ui.py`，35 项）

动态探针需要后端在跑，不适合进单测。所以把**不需要跑起来就能查**的不变量固化进
pytest，防止"改一行就悄悄回归"：

| 护栏 | 拦的是什么 |
|---|---|
| 无外链资源 | 离线/内网演示时 CDN 拿不到就白屏 |
| 内联处理器全部有定义 | B2 那一类"点了没反应 + ReferenceError" |
| `getElementById` 的目标都存在 | 选择器打错字（动态创建的 id 走白名单） |
| 菜谱行带 `data-name` | B1 的根因 |
| `agentPlan` 不再遍历 DOM 点击 | B1 的老写法（比对前先剥注释） |
| `.sbar` padding 必须严格为 0 + 子元素有省略号 | B4/B5 |
| `seekT` 有 `LAST_PLAN` 空值保护 | B3 |
| 排程页高度 = `calc(100vh - var(--chrome))` + `--chrome` 有兜底 + `fitChrome()` 被调用 | 页面被内容顶出滚动条 |
| 「已选」卡在 ③ 动态事件·重排之后 | 布局改版被改回去 |
| 列间距规则必须带 `:not(.card)` | **L1 那个选择器撞车**（见 §七） |
| `#gantt` 可滚动 + `nowline` 在 `.gantt-inner` 里 + 画布有 `min-width` | 时间轴滚不动 / 指针与泳道条基准错位 |
| `.vbtn` 必须显式 `width:auto` | 全局 `button{width:100%}` 把切换按钮撑成整行 |
| 排程页底部内边距 ≥ 60px（现为 `calc(66px + var(--sa-b))`，含安全区）+ 悬浮球覆盖规则存在 | 悬浮球压住「生成排程」主按钮 |
| `#tSlider` 必须 `appearance:none` + 背景透明 + 自绘轨道/拇指（含 `-moz-*`）+ 轨道吃到 `var(--accent)` | 退回 Chromium 原生控件皮肤（白色矩形轨道 + 蓝色圆点） |
| 滑块值 / `--p` 填充 / 读数由 `syncPlaybar()` 单点同步，且 `seekT()` 与 `render()` 都调它 | "滑块动了填充不动"、"重排后读数停在上一轮" |
| `.vbtn` 必须显式写 `color` + `box-shadow:none` | **白字压白底**（继承全局 `button{color:#fff}`）—— 按钮在、字看不见 |
| `.vbtn:hover` 必须存在且背景保持浅色 | 全局 `button:hover` 特异性更高，把未选中的按钮抢成主色，与选中态混淆 |
| `#v-plan .vbtn` 必须有 `min-width ≥ 80px` | 按钮过小 / 文本长度不同时宽度参差 |
| `.menu` 里 `show(` 恰好 5 个 + 有 `settings` 无 `devices` + `#v-devices` 不残留 | 设置站点被改回独立「设备」入口（见 §十二） |
| `.stab` 在 `:hover` / `.active` / `.active:hover` 三态下**底色必须是浅色** | 全局 `button:hover` 特异性更高 ⇒ 未选中页签被抢成主色，与选中态混淆 |
| 子面板切换只靠 `.active` 类，**不许写 `style="display:..."`** | 用内联样式切页签 ⇒ 探针/护栏都测不到，改回时静默失效 |
| 模型面板必须说明模型来自哪里（env / settings / default） | "改了没生效"最常见的原因就是被环境变量钉死，界面不说用户只能猜 |
| 设置页所有保存路径**不许出现 `alert(`** | 保存反馈必须落在页内 `.set-log`，否则移动端/自动化都看不见 |
| 设备卡必须同时给出容量数字与能力行（模式 chip） | 只给数字 ⇒ 用户不知道"蒸箱 1 台"能干什么 |
| 设置页写操作必须**同时**判 `r.ok` 与响应体 `error` | 后端两套失败契约（200+`error` / 422+`detail`），只判一样会把失败显示成"已保存"（见 §十三） |
| 错误文案必须经 `_httpMsg()` 归一 | FastAPI 的 `detail` 可能是**对象数组**，直接拼显示 `[object Object]` |
| 设备数量框留空必须拦住 | `+''===0` 而 0 是合法值（= 设备不可用）⇒ 静默把整台设备下线 |
| 数量上下限必须来自 `/api/device_spec` 的 `qty_max` | 前端写死 `max="8"`，后端蒸箱/烤箱/冰箱上限是 4（两份真源） |

护栏本身做过**变异测试**，现在有 `scripts/_mutate_web_guards.py` 一条命令跑完
（**75 / 75 全部被捕获、0 跳过**）。它**从不改动仓库里的真文件** —— 变异写进
`.workbuddy-ai/tmp/` 的副本，用 `FT_WEB_HTML` 让 `test_web_ui` 去读副本，
所以即使进程被强杀，页面文件也是干净的。

历史上踩过的两个坑：
1. `.sbar` 那条第一版写成 `padding\s*:\s*0(?:\s|;)`，被 `padding:0 8px` 蒙混过关
   （`0` 后面就是个空格）—— 已收紧为 `padding\s*:\s*0\s*(?:;|$)`。
2. `nowline` 那条第一版只查子串 `"nowline"`，而变异串 `nowline-x` 也包含它，
   于是"变异了却不报错"—— 已收紧为精确匹配 `id="nowline"`。

## 七、排程页改版：视口内自洽布局（L1）

**需求**：把「已选」卡从 ① 选择菜品 下面移到 ③ 动态事件·重排 下面；甘特图时间轴
加左右横向滚动条并拉高；任务明细收窄；模块对齐规整；**不要超出浏览器界面**。

### 改版前后（真 Edge 实测，1440×900）

| 指标 | 改版前 | 改版后 |
|---|---|---|
| 页面文档高 `docH` | **1245**（超出视口 345，出现页面滚动条） | **900 = innerH**（无滚动条） |
| 三列高度 | 1090 / 1102 / 951（参差不齐） | **759 / 759 / 759** |
| 甘特图高度 | 480（但要把页面滚下去才看得全） | **324**（始终完整可见，内部纵向滚动） |
| 甘特图 `overflow-x` | `visible`（滚不动） | **`auto`**，5 道菜时 `scrollW 1200 > clientW 826` |
| 任务明细高度 | 220 | **104** |
| 「已选」卡位置 | 左列 ① 下方 | **右列 ③ 下方** |

窗口换成 1280×720 / 1600×1000 各跑一遍：`docH` 依然**恰好等于视口高**，甘特图自动
变成 144px / 424px —— 余量全部落到甘特区，不溢出也不留白。

### 做法

```
#v-plan.active  高 = 100vh − var(--chrome)      ← 页面本身不滚动
  .grid3        三列等高，每列恰好留一个"会长大的"模块
    左列 ① 选择菜品  → #recipeList   （内部滚动）
    中列   排程面板  → #gantt        （内部双向滚动）
    右列 ② 关键通知  → #notes        （内部滚动）
```

- `--chrome` 由 `fitChrome()` 用 `nav.offsetHeight + computed top` **实测**写入
  （不是硬编码 65px），换字体/浏览器缩放都不会错位。
- 甘特图画布宽 = `max(100%, min(1200px, 110 + 计划时长 × 34px))`：计划越长画布越宽，
  超出容器就出现左右滚动条；短计划铺满容器，不为滚动而滚动。
- 泳道标签 `position:sticky; left:0` **冻结**在左侧，横向滚动时不会滑走
  （为此 `.swim` 的 `overflow` 必须是 `clip` 而不是 `hidden` —— `hidden` 会让
  `.swim` 自己变成滚动容器，sticky 就被锁死在里面永远不动）。

### 三个只有真内核才看得见的坑

## 九、视图切换按钮：可读性 + 尺寸

**需求**：「设备视图 / 菜品视图 / 人力轨道」三个按钮太小，拉长宽度；并且
**没选中时字体和背景融合了看不出来**。

后一句不是主观感受，是**真 bug**。真内核量出来：

| 按钮 | 改前 字色 / 底 / 对比度 | 改后 | 尺寸 |
|---|---|---|---|
| 设备视图（选中） | `#fff` / `rgb(17,17,17)` / **18.88** ✅ | 不变 | 66×26 → **92×31** |
| 菜品视图（未选中） | `#fff` / `rgb(253,253,253)` / **1.02** ❌ | `#111` / `rgb(253,253,253)` / **18.53** ✅ | 66×26 → **92×31** |
| 人力轨道（未选中） | `#fff` / `rgb(253,253,253)` / **1.02** ❌ | `#111` / `rgb(253,253,253)` / **18.53** ✅ | 66×26 → **92×31** |

WCAG 对比度 **1.02 = 完全看不见**（同色）；AA 正文线是 4.5。

### 两个根因（都是"全局样式泄漏进组件"）

1. **白字压白底**：全局 `button{color:#fff}` 是给橙色 CTA 用的，而 `.vbtn` 只覆盖了
   `background`（浅色毛玻璃）**没覆盖 `color`** ⇒ 继承白色 ⇒ 字消失。
   同一个泄漏还带来了橙色 `box-shadow` 光晕（`.vbtn` 也没清）。
2. **hover 抢成主色**：全局 `button:hover{background:rgba(224,90,26,.95)}` 的特异性是
   **(0,1,1)**，高于 `.vbtn` **(0,1,0)** —— 只要 `.vbtn` 不写自己的 `:hover`，
   鼠标划过未选中的按钮就会变主色橙底，界面上同时出现**两个"看起来是选中"的按钮**。

修复：`.vbtn` 显式声明 `color` / `box-shadow` / `:hover` / `.active:hover`，
`transition` 收窄到颜色相关属性（顺带把 0.3s 的全局 `all` 过渡变利落）。

### 探针新增：文字对比度 + 真实 hover

这两条都是**尺寸断言永远抓不到**的类别 —— 元素宽高完全正常，只是"看不清"。

- **对比度**：按 WCAG 公式算。背景要**逐层 alpha 合成到不透明**再比 ——
  按钮是半透明毛玻璃，直接拿 `backgroundColor` 比会得出错误结论
  （实测合成前 `rgb(255,255,255)` vs 合成后 `rgb(253,253,253)`）。
- **hover**：用 `Input.dispatchMouseEvent` 真实触发。这里踩了两个"检查自身失效"的坑：
  1. `button` 上有 `transition:all .3s` —— 派发事件后**立刻**读 `getComputedStyle`
     拿到的是过渡的**起始值**，于是"没有变橙"，检查**假通过**。
     必须 `sleep(500)` 等过渡跑完。
  2. 合成鼠标事件若没生效，同样会假通过。所以额外加一条
     「`hover` 状态真的被合成事件触发」断言（用 `querySelectorAll(':hover')` 反查）。
  **检查静默失效比 bug 本身更危险** —— 它会让你以为已经守住了。

| 类型 | 内容 |
|---|---|
| 探针实测（+6 项） | 未选中态对比度 · 选中态对比度 · hover 真的触发 · hover 不变主色 · hover 文字可读 · 按钮尺寸 ≥ 80×28 |
| 静态护栏（+2 项） | `test_view_switch_buttons_are_readable_in_every_state`（含 `color`/`box-shadow`/`:hover`/`.active:hover` 四查）· `test_view_switch_buttons_are_wide_enough` |
| 变异条目（+4 条） | 丢掉 `color` · hover 改用主色 · 选中态 hover 不再保持黑底 · 丢掉 `min-width` |

## 十、屏幕尺寸适配（P-01 收口 + 全面补断点）

**目标**：同一份 `index.html` 在 **320px 折叠外屏 ~ 2560px 超宽屏**上都不压扁、不裁切、
不横向溢出，且触摸设备上所有点击目标 ≥ 44px。

### 断点体系（源序即优先级，越窄 / 越矮越靠后）

| 断点 | 目标设备 | 关键动作 |
|---|---|---|
| `min-width:1800px` | 2K / 超宽屏 | 三列加宽上限，时间轴拿满余量 |
| 默认（> 1024px） | 桌面 | 三列等高，`#v-plan.active` 高 = `100vh − --chrome` |
| `max-width:1024px` | 平板横屏 | 触控目标 44px（**iPad 也是触摸屏**） |
| `641–1024px` | 平板竖屏 | 排程页收成单列，`#gantt` 保底 300px |
| `max-width:640px` | 手机 | `#v-plan.active` 改 `height:auto`（允许整页滚动），chip / tabs 重排 |
| `max-width:360px` | 折叠屏外屏 / 小屏 | 进一步收紧内边距与字号 |
| `(max-height:500px) and landscape` | 手机横屏 | 顶栏压缩，控件横向铺开 |

**刘海安全区**：`viewport-fit=cover` + `:root{--sa-t/r/b/l: env(safe-area-inset-*, 0px)}`。
`0px` 兜底**必须写** —— 桌面浏览器不支持 `env()` 时，整条 `calc(16px + var(--sa-r))` 会作废。
安全区落到 9 个容器（`.nav` / `.view` / `#v-plan.active` / `.fab` / `.float-panel` /
`.offline-bar` / `.llm-toast` / `.step-modal` / `.hero`）。

### 探针改造：从"固定视口"到"视口感知"

`ui_layout_probe.mjs` 新增 **§3d 多视口扫描**，用 `Emulation.setDeviceMetricsOverride`
逐个切换 11 个视口，每个视口量 8 条维度：

```
320×568 · 360×640 · 390×844 · 414×896 · 768×1024 · 1024×768
844×390 · 667×375 · 1440×900 · 1920×1080 · 2560×1440
```

断言：无横向溢出 / 导航在视口内 / 无压扁 / 无重叠 / 无捅出 / 触控 ≥ 44px /
`--chrome` 等于实测 / `--chrome` 确实随视口变化。

**三档判定**（`colTracks === 3` → 桌面口径，否则窄屏口径）：桌面要求"无任何滚动条 +
三列等高 + 余量全给时间轴"；窄屏允许整页滚动 + 单列 + 甘特图 ≥ 200px + 底部留白 ≥ 悬浮球尺寸。

**横向滚动容器内的元素不算"捅出视口"**：`.menu`（手机端 `overflow-x:auto`）、`#gantt`
（`overflow:auto`，画布 1200px）、`.tabs`、`.chips`。不排除会刷出大量假缺陷。

**截图必须非空白（新增机器化护栏）**：CDP `Page.captureScreenshot` 的 `clip` 用**页面绝对
坐标**，而代码只取了 `getBoundingClientRect()`（**视口相对**）—— 桌面端页面不滚动
（`scrollY=0`）所以看着正常，手机端整页滚动后裁到的是一片空白，而**所有数值检查照样全绿**。
现在两处 clip 都加了 `+scrollX/scrollY`，并在存盘时用内置 `zlib` 解一次 PNG、
**不同颜色 ≤3 种即判空白**（`pngStats()`）。实测：视图按钮 3× 图 1152 种颜色、
播放条 2× 图 1301 种颜色。

### 本轮抓到的 4 个真 bug（都是"数值全绿也看不出来"的那种）

1. **`fitChrome()` 在过渡中间态采样** —— 跨断点时按钮有 `transition:all .3s`，`resize`
   瞬间读 `nav.offsetHeight` 会拿到过渡中的值，把 `--chrome` **永久写错**
   （实测桌面 62 vs 65、iPad 竖屏 75 vs 122、手机横屏 72 vs 50）。
   只在切过窗口尺寸后出现、刷新就好 ⇒ **极难复现**。
   修复：挂 `ResizeObserver` 持续重算 + 值未变不写 DOM。
2. **`.chip` 不是 `button`** —— 吃不到全局 `min-height:44px`，手机上实测只有 38px。
   修复：手机与平板断点各加 `.chip{min-height:44px}`。
3. **触控判据只覆盖 ≤640px** —— iPad 768×1024 是触摸屏却按鼠标对待，8 个控件不足 44px。
   修复：平板断点补完整触控块 + 探针 `touch` 阈值改 `max-width:1024px`。
4. **局部截图 `clip` 少加 `scrollX/scrollY`** —— 桌面端看不出（不滚动），手机端整页滚动后
   截出的是一张纯色空白图，而数值全绿。修复见上面「截图必须非空白」一段。

### 页面结构

```
#v-settings
├── .subtabs#setTabs
│   ├── .stab[data-tab="model"]    模型接入
│   ├── .stab[data-tab="devices"]  厨房设备
│   └── .stab[data-tab="token"]    访问令牌

```

切换**只靠 `.active` 类**（`setTab()` 同时管 `.stab` 与 `.spanel`），**不许写 inline style** ——
写内联样式的话，静态护栏与探针都只能"看见"默认那一屏，改坏了也没人知道。

### 模型接入：三层优先级

模型名不是"设置里存什么就用什么"，而是三层覆盖：

```
FT_LLM_MODEL（真实环境变量）  >  data/llm_settings.json（设置页写盘）  >  provider 内置默认
```

`llm.MODEL_SOURCE` 会告诉前端当前生效的是哪一层，界面**必须把这行显示出来** ——
"我在设置里改了模型但没生效"最常见的原因就是被环境变量钉死了，不显示来源用户只能猜。
被钉死时 `llm.model_locked()` 返回一段**可照做的中文说明**（去哪个文件删哪一行），
下拉同时禁用。

三个只有踩过才知道的点：

1. **列模型不能走 OpenAI 兼容层。** Ollama 的模型列表在原生 API `GET {root}/api/tags`，
   **不在 `/v1` 下**。`BASE_URL` 是 `http://127.0.0.1:11434/v1`，直接拼会去请求
   `/v1/api/tags` 拿 404。所以有 `_native_root()` 专门把尾部 `/v1` 去掉。
2. **换模型之后必须 `breaker_reset()` + `reset_online_gate()`。** 否则会出现
   "明明换成了更快的模型，闭环还是被闸门挡着"—— 因为熔断器/闸门记的是**上一个模型**的失败。
3. **失败绝不静默成功。** 非法模型名 `raise HTTPException(400, detail=...)`；
   写盘失败也要让前端拿到 `ok=False`。前端 `saveModel()` 判的是响应体里的 `error` 字段
   而不是 HTTP 码（后端非法配置返回 200 + `error`），两处判据要一致。

### 厨房设备：卡片式

`GET /api/device_spec` 从 `spec/device_spec.py::DEVICE_SPEC` 取每台设备的
`default_mode` / `modes` / 温度包络。**包络取所有模式的 min/max** ——
只看"空气炸"这一个模式会误以为烤箱最低 180℃。

前端 `loadDevices()` 里 `catch{spec={}}` 兜底：设备能力接口拿不到时，
容量编辑框仍要能用（容量在 `/api/devices`，能力在 `/api/device_spec`，是两个来源）。

### 访问令牌

令牌**只从 `?token=` / `localStorage` 取，绝不硬编码**。`AUTH_TOKEN` 是
`localStorage` 的**内存镜像**，`saveToken()` 写完存储之后**必须从存储读回**
（`AUTH_TOKEN = localStorage.getItem('ft_token') || ''`）—— 否则隐私模式下
"写失败但内存里是新的"，刷新后行为不一致。存储不可用则只留内存并提示。

## 十三、设置页写操作的 4 个静默失败（漏洞审计，本轮）

这一轮不是"看代码觉得有问题"，而是**先发真实请求取证**再改。四条都有实测复现。

### 13.1 后端有**两套**失败契约 —— 只判一样就会把失败显示成成功

| 场景 | HTTP | 响应体 |
|---|---|---|
| 业务校验失败（设备数量超范围、模型名非法…） | **200** | `{"error": "...", "details": [...]}` |
| 请求没被路由接受（Pydantic 参数校验） | **422** | `{"detail": [{"type","loc","msg"}, ...]}` |
| `HTTPException` | 400 | `{"detail": "中文原因"}` |

**实测**：`curl -X POST /api/devices -d '[]'` → `422 {"detail":[{"type":"dict_type",...}]}`。

而 `saveDevices()` 当时只判 `d.error` —— 422 的响应体里没有 `error` 键 ⇒ `undefined` ⇒
一路走到 `_setLog('setDevLog','设备配置已保存，下次排程生效。','ok')`。**保存失败了，界面说成功了。**

修法：`saveDevices` / `saveModel` 都补 `if(!r.ok)`，与 `d.error` 一起判。

### 13.2 `detail` 有两种形状，直接拼会显示 `[object Object]`

`HTTPException` 给字符串，Pydantic 422 给**对象数组**。旧代码
`'保存失败：'+(d.detail||d.error||...)` 遇到数组会拼成 `[object Object]` ——
用户看到等于没看到，还会把"参数不对"误判成"后端坏了"。

修法：新增 `_httpMsg(d,r)` 统一归一（字符串直用 / 数组取 `msg` 拼 `；` / 否则回落 `HTTP <code>`）。

### 13.3 数量框清空 ⇒ **静默把整台设备下线**

JS 里 `+'' === 0`，而 **0 在设备配置里是合法值**（表示该设备不可用）。
不拦的话，"手滑清空一格再点保存"会静默把整台设备下线：相关步骤全部改走顶替/人工，
排程结果大变，而界面只回一句"已保存"。

浏览器还会把 `1e`、`-` 这类半截输入也归成空串，所以这条拦得住真实手滑。

修法：空值直接拦下并说明「0 表示该设备不可用」。

### 13.4 数量上下限的**两份真源**

后端 `app/api/main.py::_DEVICE_LIMITS` = 灶眼数 `(0,8)` / 蒸箱·烤箱·冰箱 `(0,4)`，
而前端给**所有**设备都写 `max="8"` —— 用户在界面上给蒸箱填 8 是**合法操作**，
提交才被后端判非法。同一件事有两份真源，改一处必然漏另一处。

修法：`/api/device_spec` 下发 `qty_min` / `qty_max`，前端改绑；护栏钉住"下发值 == 校验值"。

### 13.5 ⚠ 顺带抓到**自己的护栏失去牙齿**（最值得记的一条）

复跑变异套件拿到 `74/75`，唯一 `[BAD]` 是「设备卡不再展示能力信息」**捕获=False**。

根因：本轮在 `loadDevices()` 里加了一句注释提到 `/api/device_spec`，而护栏断言写的是
`"/api/device_spec" in body` —— **注释把变异"喂饱"了**：把真正的
`apiFetch('/api/device_spec')` 调用整条删掉，字符串还留在注释里，护栏照样绿。

修法：断言改成查**调用点** `apiFetch('/api/device_spec')`。
复验 `捕获=True 还原=True`。

> 又一次印证：**"字符串出现"不等于"代码在跑"**。护栏要查的是**行为**，
> 而不是"这个词有没有在文件里出现过" —— 新增代码里的一句注释就足以让它失效。
