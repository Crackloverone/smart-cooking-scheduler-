# 模型配置随包分发（开箱即用 + 密钥打码）

> 落地日期 2026-10-06 · 触发问题：**"迁移程序时 API 调用的配置被抹掉了，别人拿到之后调不了 API。"**
> 验收方式：`python -m pytest -q`（全量）· `python -m scripts._mutate_llm_guards` · `python -m scripts._mutate_web_guards`
> · `node scripts/ui_probe_llm_off.mjs` · `node scripts/ui_probe.mjs` · `node scripts/ui_layout_probe.mjs`

---

## 0. 一句话结论

模型接入配置从**两层**（用户层 + 代码常量）扩成**五层**，
新增一层**随包分发的出厂默认配置**（`app/agent/llm_defaults.json`），
让接收方解压后**不用配任何东西就能调模型**；密钥在前端只显示**打码预览**（前 6 + 后 4），
既不删掉、也不回传原文。

| 诉求（用户原话） | 落点 |
|---|---|
| "api 调用的配置被抹掉了，别人拿到无法调用" | 新增出厂层 `app/agent/llm_defaults.json`（随 `app/` 一起进 publish / zip） |
| "前端对 key 打上马赛克就好了，不用进行删除" | `llm.mask_key()` + `remote_view()/factory_view()/llm_status` 回 `api_key_masked`；界面标签行显示 `sk-pro1…ESb0`，输入框仍留空 |
| "添加默认自带的配置，第一时间就能用" | 出厂层给足 `provider / base_url / api_key / model`，接收方 `enabled()==True`、`state=online` |

## 1. 问题是怎么来的

改造前只有两层：

```
真实环境变量 > data/llm_settings.json（用户层） > 代码里的 _DEFAULTS
```

- `data/llm_settings.json` 是设置页保存的**本机选择**，被 `scripts/sync_publish.py`
  **刻意排除**（跟着进发布目录会让线上带着开发机选的模型名启动 ⇒ 404 ⇒ 静默降级）；
- `data/devices_user.json`（选择厨房写下的设备台数）**同类，同样排除** ——
  `sync_publish.SKIP_NAMES = {"llm_settings.json", "devices_user.json"}`，
  护栏 `test_本机状态文件都不进发布包`（`tests/test_deploy_windows.py`）钉住这两条；
  与"出厂层"要分清：`data/device_presets.json` 是**产品数据**、必须随包走；
  界面上的「选择厨房 → 恢复默认」走 `POST /api/devices/reset`：把内存与引擎都
  拨回 `_DEFAULT_DEVICE_CFG`（2/1/1/1），**并把这份用户层文件删掉** ——
  "恢复默认"是回到出厂状态，不是"把默认值当成一次用户选择存下来"；
- 代码里的 `_DEFAULTS` 只写 `http://127.0.0.1:11434/v1`（本地 Ollama，免密钥）——
  源码里没有凭据，但**接收方必须自己配一遍**才能用上模型。

于是"发出去"和"能直接用"这两个目标互相打架：**任何一层的凭据都不在包里**。
接收方拿到程序 → `provider=ollama` → 本机没装 Ollama → AI 静默降级成规则兜底，
页面上**没有任何报错**。

## 2. 现在的五层解析

```
真实环境变量
  > data/llm_settings.json      用户层（设置页写的；sync_publish 刻意排除）
    > app/agent/llm_defaults.json  出厂层（随源码 / 发布包走）← 本次新增
      > llm._DEFAULTS              代码常量（不带任何凭据）
        > 兜底常量
```

实现位置：`app/agent/llm.py`

| 函数 | 职责 |
|---|---|
| `_read_defaults()` | 读出厂层；缺失/损坏**一律当空**并回落代码默认（接收方删掉这个文件也要能跑） |
| `_layer(factory)` | `factory=None` ⇒ 用 import 时的快照 `_FACTORY`（缺省故意不是"空"，见下） |
| `_resolve_provider/_resolve_base_url/_resolve_api_key/_resolve_model` | 五层逐个取第一个"给了值"的层 |
| `factory_view()` | 出厂层现状（诊断 / 界面用），**只给打码预览** |

**`_layer()` 的缺省为什么不是空**：两个方向都会静默出错，但后果不对称 ——
缺省=空 ⇒ 以后谁新加一个调用点忘了传 `factory`，出厂层整层失效，接收方又拿不到配置
（就是这次要修的问题）；缺省=真出厂层 ⇒ 最坏只是测试要显式传 `{}`（会立刻红）。

**用户层永远整层优先**：接收方在设置页改过之后，重新发一版程序**不会**抹掉他的改动 ——
这是"出厂层放在 `app/`、用户层放在 `data/`"的直接结果，不是靠额外的判断逻辑。

### 2.1 出厂层文件

`app/agent/llm_defaults.json`（形状与用户层一致，便于互相复制）：

```json
{
  "provider": "openai",
  "remote": { "base_url": "https://<中转站>/v1", "api_key": "sk-..." },
  "models": { "ollama": "qwen2.5:7b", "openai": "gpt-5.6-sol" },
  "model":  "gpt-5.6-sol"
}
```

`_note` 之类的额外键会被忽略（json 不支持注释，用它写说明）。

**轮换 / 换站**（三种，按影响面从大到小）：

1. 改这个文件 + 重新打包 —— 影响所有接收方；
2. 设环境变量 `FT_LLM_API_KEY` / `FT_LLM_BASE_URL`（**优先级最高**）—— 只影响这一台；
3. 在设置页填自己的地址与密钥并保存 —— 落用户层，**压过出厂层**，重新发版也不被覆盖。

**彻底关掉随包凭据**：删掉 `remote` 块、或把 `provider` 改回 `"ollama"`。
两种改法都不需要动代码。

### 2.2 三条分发通道都要能带上它

| 通道 | 机制 | 现状 |
|---|---|---|
| Windows zip（`deploy/windows/pack.ps1`） | 从 `publish/` 取；`sync_publish` 全量同步 `app/` | ✅ 已加**包内复核**：缺 `app/agent/llm_defaults.json` 直接 `Die` |
| 线上发布（`publish/`） | `sync_publish` | ✅ 自动带上（`.json` 不在排除后缀里） |
| Docker 镜像 | `Dockerfile` 是 `COPY app ./app`；`.dockerignore` 排除 `data/llm_settings.json` 与 `.env*` | ✅ 出厂层不受影响 |

⚠ **容器里默认仍是 `FT_LLM=off`**（`Dockerfile` 的 `ENV FT_LLM=off FT_AGENT_LLM=off`，
是**全局总闸**，出厂层**不会**绕过它）。容器里要开 AI，运行时显式传 `FT_LLM=on`。

## 3. 密钥打码

### 3.1 后端

| 位置 | 行为 |
|---|---|
| `llm.mask_key(k)` | 前 6 + `…` + 后 4；`len(k) < 12` ⇒ `"***"`（露头露尾等于把整把钥匙给出去） |
| `llm.looks_masked(v)` | 含 `…` 或 `***` ⇒ 判为打码预览。真实密钥只含 `[A-Za-z0-9_-]`，不会命中 |
| `remote_view()` | 回 `api_key_masked`（**绝不回原文**）；`base_url/model` 回用户层保存值（输入框回填用），`effective_*` 回**生效值** |
| `factory_view()` | 出厂层现状，同样只给打码预览 |
| `GET /api/llm_status` | 新增 `api_key_masked`（顶部徽标 tooltip 用） |
| `GET /api/model_settings` | `remote.api_key_masked` + 新增 `factory_defaults` 块 |
| `set_provider()` | 提交的 `api_key` 若形如掩码 ⇒ **400 拒绝**，且**一个字节都不写盘** |

**为什么"打码预览"可以回传，而"密钥原文"不行**：`/api/model_settings` 是**无鉴权公开**的
（本机演示 / 发布出去的链接都能读）。前 6 + 后 4 只够辨认"是哪一把钥匙"
（换过 key 之后最需要这个信息），中间的熵不外泄；再加上后端拒绝把掩码写回去，
这个字段就是安全的。只回"已配置"是不够的 —— 用户没法确认配的是哪一把，
于是会反复重填、把本来好着的配置改坏。

### 3.2 前端（`app/web/index.html`）

- **标签行**显示 `远程 API Key 已配置：sk-pro1…ESb0`（`#setRemoteKeyNote`，
  inline 放在 `.set-label` 里 —— 新增块级元素会撑高卡片，那类"悄悄挤一下布局"的改动
  只有真浏览器排版探针看得见）；
- **输入框保持空**（`rk.value=''`），占位文字仍是「已配置（留空 = 不修改）」；
  把打码值填进 `value` 是个坑：用户随手点一次「保存」就会把它当密钥提交；
- **提交前拦截**：`looksMaskedKey(k)` 与后端**同款判据**，命中就报错并 `return`，
  值不进请求体；
- **状态表 / 徽标 tooltip** 都带打码预览；
- **出厂预置提示**：用户层为空 + 出厂层存在 ⇒ 明确写"远程那一栏现在用的是
  **随程序附带的出厂预置**，在下面填了自己的地址 / 密钥并保存后，就以你的为准"。
  不说这句，接收方会以为是自己配好的，之后换机器完全不知道该去哪儿改。
- `model_source == "factory"` 映射成「出厂预置（随程序附带）」，
  避免把英文枚举直接显示给用户。

## 6. 明确不做 / 已知取舍

1. **密钥是明文随包分发的**（这是用户明确要求："发出去别人第一时间就能用"）。
   代价：拿到包的人就拿到这把钥匙。缓解：环境变量可整层覆盖；用户层可整层覆盖；
   删 `remote` 块或改 `provider` 即可关掉。**轮换密钥 = 改这一个 json + 重新打包。**
2. **不把用户层打进包**（`sync_publish` 仍排除 `data/llm_settings.json`）。
   理由不变：那是"本机选择"，进包会让线上带着开发机的模型名启动。
3. **不做前端"显示/隐藏密钥"按钮**：原文根本不出后端，这个按钮没有可显示的东西。
4. **不做多套出厂 profile**（如"演示档 / 离线档"）：现在只有一份，需要时用环境变量切。

## 7. 踩过的坑（写给下一个改这里的人）

1. **变异脚本被强杀 ⇒ 源码留在被改过的状态。**
   `_mutate_llm_guards.py` 前台跑超时被 SIGTERM，`finally` 没执行，
   `llm.py` 里的 `looks_masked()` 被留成了 `return True`（之后所有真密钥保存全被误拒）。
   现在两个 Python 变异脚本都装了 SIGINT/SIGTERM 处理器 + 开头自动还原；
   **判断"有没有残留"必须比 sha256，不能只看几个锚点还在不在** —— 那次锚点全在。
2. **`publish/` 是拷贝**：源码被改坏之后跑一次 `sync_publish`，坏代码就进 publish 了。
   改完源码 → 跑测试 → 再 sync。
3. **前端"打码"和"不回填"必须同时成立**：只打码不回填 ⇒ 用户认不出是哪把钥匙；
   回填 ⇒ 保存一次就写坏配置。
4. **新增块级元素会挤布局**：打码预览放在 `.set-label` 行内，
   不新开块（理由见 §3.2）。

## 8. 打包成 zip（云服务器部署）

```powershell
powershell -ExecutionPolicy Bypass -File deploy\windows\pack.ps1
# 产物：dist\cooking-agent-windows.zip（约 0.42 MB / 73 个文件）
```

`pack.ps1` 会先强制 `sync_publish` + `--check`，再打 `publish/` + `deploy/`，
最后做三项复核：**必需文件在包里**（含 `app/agent/llm_defaults.json`）、
**`.env*` 不许进包**、**条目名必须是正斜杠**。

### 8.1 云服务器上注意两条

1. **不要用 `-Offline`**。`setup.ps1 -Offline` 写的是 `FT_LLM=off`，那是**全局总闸**，
   会把出厂层预置的远程配置一起关掉（设置页改不动它）。要开箱即用就直接跑：
   ```powershell
   powershell -ExecutionPolicy Bypass -File C:\cooking-agent\deploy\windows\setup.ps1
   ```
2. **服务器上会写 `FT_WARM_LLM=off`**（关掉启动探测）。理由见 §8.2 —— 这是**对的**，
   别"顺手打开"。

### 8.2 为什么服务器上要关掉启动探测（2026-10-06 复核后改写）

原来的注释写的是「服务器上没有本地 Ollama，默认的 **60s** 启动探测会白等一分钟」——
那是**出厂档还是本地 Ollama** 时的话。现在出厂层是**远程**档，探测预算变成 **1.5s**
（`llm._DEFAULT_WARMUP`），理由完全变了：

- 首次调用要先建 TLS 连接，实测冷启动常落在 **1.5s 上下**（实测单次 1.47s）；
- 探测超时的后果不是熔断，而是 `mark_online_too_slow()` 把**在线闭环**关掉
  （排程退回规则兜底）—— 等于白少一路 AI 策略；
