## 已上线（方案 A 一键发布）

**线上地址：https://cooking-agent.app.workbuddy.host/**

### 发布做法（可复用）
1. 发布工具会压缩上传**整个目录**，项目根有 `.venv`(219M)、图片、docx/pptx，
   直接发布会又慢又可能失败。→ 先生成精简目录 `publish/`（53 文件 / 4.7MB）：
   只含 `app/ data/ scripts/ requirements.txt`，排除所有点开头目录（.venv/.cache/
   .pytest_cache/.workbuddy*）、`__pycache__`、png/docx/pptx、data 下的 `*_report.json`。
2. 发布参数：
   - `directory`: `D:/Xuzj/ky/Project/ft/publish`
   - `installCmd`: `pip install -r requirements.txt`（含 ortools，云端装得动）
   - `startCmd`: `FT_LLM=off FT_AGENT_LLM=off uvicorn app.api.main:app --host 0.0.0.0 --port ${PORT:-8000} --workers 1`
   - `port`: 8000；`domainPrefix`: `cooking-agent`
3. 线上关掉模型调用（`FT_LLM=off`）保证响应快、零外部依赖；语义先验仍从
   `data/llm_agent_cache.json` 读取，模型产物照旧生效。想打开模型决策就把
   startCmd 里的两个 `=off` 去掉（但模型端若慢会逼近 5s 评分线）。
4. 发布前**先在本地用 publish/ 目录起一次服务**验证自包含（我验证过：
   /health /ready /api/plan /app /api/recipes /api/profiles 全通）。

### 线上实测（发布后）
`/health` ok、`/ready` {"ready":true,"recipes":100}、`/api/plan` 200(455ms 含网络)、
`/app` 200(58KB)、菜名 100 道。

### 线上不依赖本机（已实证）
发布后关掉本机全部服务（`netstat` 无任何 8000/8137/8201/8202 监听、无 python 进程），
线上链接仍全部 200：`/health` 0.5s、`/api/plan` 0.43s、`/app` 58KB。
→ 代码已托管在云端沙箱，**不需要用户开机、不需要本地起服务**。
公开 https，任何人无需登录即可访问。

### 保活风险（待观察，尚未证实）
托管沙箱是否会在长时间无人访问后休眠/回收，尚不确定（发布后 8 分钟实测仍是热的一
0.5s 响应）。判断方法：隔几小时再访问一次，看 `/health` 是否仍在 ~0.5s；
若变成数秒甚至需要重新安装依赖，说明被回收了。
→ 正式答辩/评分场景建议改用方案 C（自己的云服务器），避免现场冷启动。

### 注意
- 重新发布用**同一个 publish 目录**即可覆盖，链接不变。
- 改了源码后要**重新生成 publish/**（它是拷贝，不是链接），否则线上还是旧代码。

## 平台子域名不可改名（已实证，别再试）

用户想把 `cooking-agent.app.workbuddy.host` 改成 `cook-scheduler` / `Xzj666`。

**结论：改不了。**
- 新建 `publish-v2` 目录并用 `domainPrefix: "cook-scheduler"` 发布 → 仍返回
  `https://cooking-agent.app.workbuddy.host/`，且 `sandboxId` 与原来完全相同
  （`4cac88ed...`）→ 平台只是**覆盖**了原应用，没新建。
- `https://cook-scheduler.app.workbuddy.host/` 实测 **HTTP 404**。
- 工具 schema 原文：`domainPrefix` "requests a custom first segment **when a new app
  is created**"；"Publishing is ALWAYS an overwrite: there is no parameter for creating
  a second app alongside an existing one — that is done from Settings - Data Management".
- 前缀还必须是小写字母/数字/连字符（≤32），大写会被规范成小写。

→ 想拿到自选域名只能走**方案 C 绑定自有域名**。要换平台前缀的唯一可能是去
「设置 → 数据管理 → 已发布应用」删掉再建，代价是旧链接立即失效（属破坏性操作，
动手前必须二次确认）。

### 决策
用户选择：**保留 cooking-agent，把方案 C 的域名接入步骤补全**。
