## 本轮修掉的 3 个真 bug（都是冒烟时暴露的）

1. **`/api/agent_plan` 绕过统一 LLM 客户端**：自己发 urllib、`timeout=30`，
   不共享超时/熔断/缓存；且把 `HTTP Error 429` 原文直接返回客户端，模型不可用时整端点废掉。
   → 改走 `llm.chat_json`；新增 `objective.rule_pick()` 规则选菜兜底；
   响应改为 `{picked, plan, source, notice, elapsed_ms}`，错误只在服务端 `_LOG.warning` 留痕。

2. **`adapter._category_of` 分类不可信**：把步骤全文纳入匹配且"汤"优先于"蒸/烤"，
   步骤里的"倒掉汤汁""蒸箱预热"噪声导致 豉汁蒸草鱼→汤羹炖品、苹果芒果派→蒸箱料理。
   前端按 category 做筛选，是用户可见的错误。
   → 改为菜名优先（强信号），步骤只在菜名无信号时作弱信号（只认蒸箱/烤箱/炖煮等词）。

3. **`rule_pick` 补位把 minutes=0 当最快**：minutes=0 是"未识别时长"不是"0 分钟"，
   补位补出来全是解析失败的菜。→ 排序 key 改为 `(mins<=0, mins)`。

## 约定/经验

- 本项目的模型调用**必须**走 `app/agent/llm`，任何模块自己发 HTTP 请求都会绕过

- 模型端今日 token 额度用完会返回 429；`llm` 已做分级熔断（429 立即熔断 1800s）。
