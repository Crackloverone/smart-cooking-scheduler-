# 追加：两处「恢复默认」按钮（同日第二轮）

用户指令：`动态事件的重排模块添加一个恢复默认的按钮，点击后恢复默认；`
`选择厨房场景也同理，点击按钮恢复默认`。

## 一、实现

| 模块 | 做法 | 默认值的**唯一真源** |
|---|---|---|
| 动态事件 · 重排 | `resetEvent()`（**纯前端**）：`#eventType` → `EVENT_DEFAULT='insert'`、清 `#insertPick`、走 `onEventChange()` 清旧摘要、写一句反馈。**不自动重排** | `<select id="eventType">` 的第一项（用**显式常量**，不读 `options[0]`） |
| 选择厨房 | `resetKitchen()` → `POST /api/devices/reset`（**新增后端端点**）：内存+引擎拨回 `_DEFAULT_DEVICE_CFG`（2/1/1/1），**并删掉 `data/devices_user.json`** | 后端 `_DEFAULT_DEVICE_CFG`（前端**不写死**） |

为什么事件那处**不**自动重排：`failed_device` 是 `/reschedule` 的**请求体字段**，
按请求生效、不粘在进程里 ⇒ 没有需要清的服务端状态；而重排要跑 5~20s，
用户点"恢复默认"不会预期按钮转二十秒。反馈文案里必须写明"计划仍是上一次重排的结果"。

为什么厨房那处**不能**走 `POST /api/devices` 发默认值：那会把"默认值"当成一次
用户选择**落盘**，以后后端改默认值这台机器会顽固地停在旧默认上。
也不能让前端抄一份默认值：后端改了前端不会跟着变，且没有任何报错。

## 二、踩到的坑

1. **真 Edge 排版探针抓到真回归**：两处按钮都放右栏，667×375（iPhone 8 横屏、3 列）
   下右栏只有一百来像素 ⇒ `#eventResetBtn` 捅出视口（`@670` vs 视口 667）。
   **修法**：容器 `flex-wrap:wrap` + 第一个按钮 `min-width:0`（窄屏自动落到第二行）。
   ⚠ 只加 `min-width:0` 不够 —— 那只会把「应用重排」挤成一条缝。
   jsdom 探针与 pytest 全程全绿，**只有真 Edge 会红**。
2. **护栏判据被同行文本兜住（两次）**：
   - `assert "insertPick" in fn` —— `const pick=getElementById('insertPick')` 已经把
     那个词带进来了，删掉复位那一行照样绿。改成钉**赋值** `\bpick\.value\s*=`。
   - `assert re.search(r"d\.error", fn)` —— `if(!r.ok){` 后面那句
     `const why=(d&&d.error)?…` 仍带着 `d.error`，去掉 error 判定照样绿。
     改成**取 if 条件**、要求同一条条件里同时有 `!r.ok` 与 `d.error`。
   - ⚠ 取条件不能用 `\(([^)]*)\)`：条件里有嵌套括号 `(d&&d.error)`，
     `[^)]*` 会停在**内层** `)` 上 ⇒ 一条都匹配不到 ⇒ 断言恒假（还原后也红）。
     用非贪婪 + 禁止跨行：`if\s*\(([^\n]*?)\)\s*\{`。
3. **新增代码会撞掉既有变异锚点**：`resetKitchen` 里出现了与 `applyKitchen` 相同的
   `if(!r.ok||(d&&d.error)){` 和 `const note=getElementById('kitchenNote');`
   ⇒ 两条旧锚点从 1 次变 2 次、被标 `[跳过]`。修法：把锚点加长到含
   `切换失败` / `const p=PRESETS[name];` 这类**函数独有**的上下文。

# 追加：排程页顶栏「穿模」+ UI 与其他站点不一致（同日第三轮）

用户指令：`智能排程界面的ui与其他站点不一致，上方的模块和导航栏穿模了`

## 一、根因（一个 CSS 语义坑）

`.nav` 是 `position:sticky`，而 **`top` 只挪渲染位置、不占文档流空间**：
顶栏渲染在 `14..65`，但在流里仍只占 `0..51` ⇒ 紧跟其后的 `#v-plan` 从 51 开始，
**首行模块顶部 14px 永远压在顶栏底下**。

**为什么只有排程页明显**：`.view` 写 `padding-top:28px`，`28 > 14` **侥幸**躲开；
`#v-plan` 自己写 `padding:10px`，`10 < 14` ⇒ 被压 4px + 顶栏投影。
即这条 bug 靠"某个数字恰好比 14 大"掩盖，**不是**结构性保证。

## 二、修法

新增两个唯一真源变量（各断点只覆盖变量本身）：
- `--nav-top:calc(14px + var(--sa-t))` —— **同时**用在 `.nav` 的 `top` 与 `margin-top`。
  `margin-top` 让流内位置 = 渲染位置 ⇒ `--chrome`(= 顶栏下沿) 与文档流自洽。
- `--page-top-gap:14px` —— 全站（含 `#v-plan`）唯一的顶部留白。

⇒ **每一个桌面视口都红**，排程页压得最狠。改动后同视口 **117 / 0**。

## 四、顺带修掉：矮视口下三列仪表盘整体崩坏

仪表盘成立前提 = 「右列最小内容 606 + 顶栏 65 + 底部留白 78 + 顶部间距 14 塞得进视口」
= **视口高 ≳ 763px**。再矮必然同时：① 甘特图被压成 0（`1084×570` 实测）；
② 右列溢出、悬浮球压住「生成排程」；③ 内容顶高 `<body>` ⇒ 出滚动条 + 顶栏浮在内容上。
新增 `@media (min-width:1025px) and (max-height:760px)` **换布局档**（长页），
与平板/手机同策；阈值 760 是算出来的（763 临界，1366×768 仍留仪表盘档）。
另修 `.float-panel` 写死 `height:520px` 在矮视口从 top 捅出视口 ⇒ 改 `min(520px, calc(100vh - …))`。

## 五、踩到的坑

1. **护栏断言被 CSS 注释兜住**（铁律②的 CSS 版）：长页档里
   `#v-plan .grid3{flex:none;align-items:start}` 上方那段解释性注释**同时写着**
   `flex:none` 与 `align-items:start` ⇒ 删掉真声明后 `"align-items:start" in body`
   照样为真。变异自检实测报
   `[BAD] 长页档丢掉 align-items:start  变异后被捕获=False`。
   修法：新增 `_strip_css_comments()`，断言前先剥注释（**已实测变异后必红**）。
2. **改 CSS 会批量撞掉既有变异锚点**：本轮把 `padding:10px` → `var(--page-top-gap)`、
   `top:calc(14px + …)` → `var(--nav-top)`，一次性让 **4 条**旧锚点从 1 次变 0 次
   （`排程页高度改回按内容撑高` / `排程页底部不再给悬浮球留白` /
   `顶栏不再让出安全区` / `手机断点里排程页重新锁死视口高度`），全被标 `[跳过]`。
   ⇒ **凡是要改一条"被变异锚点引用的 CSS 声明"，必须同一次改掉锚点**。
   修完补了"锚点唯一性预检"：一次性跑完全部 136 条 `html.count(old)==1`。
3. **探针不能自己再抄一份断点阈值**：三档布局（桌面仪表盘 / 矮桌面长页 / 堆叠）
   硬要求互斥。判档信号取**实测值** `#v-plan .grid3` 的 `align-items`
   （`stretch`=仪表盘、`start`=长页）—— 它同时被 CSS 与探针使用，是唯一信号。
4. **扫描表的空档就是真回归的藏身处**：`VP_LIST` 原来 11 个视口里有 `1024×768`
   与 `844×390`、`667×375`，**恰好漏掉"宽 >1024 且高不到 800"** ⇒ 上面那条崩坏
   一路没被发现。已补到 **14 个**。
5. **残留 `scrollY` 让穿模守卫假失败**：上一节局部截图用过 `scrollIntoView`，
   桌面尺寸文档不够高（`scrollY` 恒 0）所以从没暴露；切到窄屏后残留生效 ⇒
   `320×568` 量到"首行顶=-563"。修法：扫描循环里切视口后先 `window.scrollTo(0,0)`。
6. **`#v-home` 是满幅落地页**，首行间距 **0 是有意的** ⇒ 一致性比对必须排除它
   （否则报 `home=0 plan=14 …` 假失败）。
