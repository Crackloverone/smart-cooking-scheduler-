## 任务：以评委视角评审「智能烹饪调度 Agent」排程算法，并产出完整算法建模

### 产出
- `docs/调度算法建模.md` — 评审版建模文档（评分卡 / 排程重点辨析 / 8 项缺陷 / 完整数学模型 / 实测对比 / 落地清单）
- `app/scheduler/model.py` — 精确参考实现（新增，约 430 行）

### 核心结论
1. **赛题 100 分中排程占 70 分**（并行调度 25 + 多目标 25 + 动态重排与通知 20）。自评总分 ≈76。
2. **排程四要素分属三类数学对象**：冲突/依赖=硬约束（绝不能进目标函数）；总时长/出锅差/连续手动=目标；
   设备利用率=导出指标（是仪表盘不是方向盘，不该进目标）。
3. **关键缺陷**：现有引擎把 3 个目标压成硬编码常数，且"出锅差"写成 `max(F)-min(F)` 是**可博弈伪目标**
   （拖到最后就能刷小）。正确写法是以"上桌时刻 T"为锚的加权冷等待 `Σ σ_d·(T-F_d)` + 保热上限 ρ_d。
4. **连续手动操作时长（25 分单列项）原项目完全没有建模**，只在 metrics 里被统计。

### 精确模型新增的建模要素
- **C3 批次机（batch machine）**：同温档 `AddCumulative(Q_k)`，异温档两两 `AddNoOverlap` —— 让求解器主动凑炉，而非事后放行
- **C5 连续手动上限**：时间索引 ω_t 精确线性化 + "不存在 B+1 分钟连续忙碌"约束；B ≥ max 单步时长（否则不可行）
- **两阶段 ε-约束目标**：阶段1 min T，阶段2 min 语义出锅差 s.t. T ≤ T*+ε —— 替代拍脑袋的加权和
- **批次机感知下界**：`LB_k = Σ_b ceil(busy_b / Q_k)`。教科书公式 `ceil(Σp/c)` 对本问题是**错的**（会高估，导致出现 makespan < LB 的自相矛盾）

### 本轮新发现的 5 个缺陷（比第一轮 D1–D8 更值钱）
- **D9 目标与评分表口径不一致（最贵）**：赛题原文"出锅时间差 = **最后一道菜与第一道菜完成的时间差**，<5min 优秀" ⇒ 就是原始跨度 `max F - min F`。而我第一版优化的是语义冷等待 `Σσ_d(T-F_d)`，两者在"冷菜可早出锅"时**方向相反**。教训：**先抄评分表公式，再谈建模深度**。
- **D10 `_bucket(None)` 把"温度未标注"当独立温度档**：独立档与所有档两两互斥 ⇒ 强制独占一炉。139 个蒸/烤步骤中 49 个(35%)温度未解析，受影响实例 +54%（74→114min）。
  踩过的坑：看似"让求解器选档"更优，但**做不到** —— 同一任务的两个候选档会落进同一个 `AddNoOverlap` 列表，反而禁止它与本档成员并行（实测 86→96）。**必须在数据层定温度**。
- **D11 `lb_cp` 用"菜内时长求和"代替关键路径**：菜谱有并行分支（如"浸泡3min"与"上锅蒸15min"互不依赖），求和在 80 组里踩中 1 组，报出 `总时长 42 < 下界 46`。
- **D12 两阶段目标存在并列最优 → 结果不可复现**：阶段2 只 min 出锅差时，`[T*, T*+ε]` 内同出锅差的解并列最优，求解器返回哪个 T 是任意的 —— 同一实例随机报 74 或 79min。**必须把 T 钉进目标**。
- **D13 hand_cap 编码过重 → 静默失效**：时间索引 ω_t 是 O(n·H)，5 菜实例 4725 布尔 + 13959 项。**3s 预算下 7/8 组解不出来**，阶段1 返回 UNKNOWN，`_give_up()` **静默丢弃约束**（报出的 54min 其实没受约束）；12s 才 0/8 回退。且 B 定义（严格无空闲）与 `metrics.hand_streak`（允许 1min 空隙）不一致。

### 关键实现约定（改代码前必读）
1. **`allow_preprocess` 默认 True**（`solve_exact` / `solve_with_gap` / `solve_lns`）。必须与 engine 的 prep_ahead 口径一致，否则两轨排**不同任务集**，精确解被迫把备菜步排进人工池（`lb_hand` 直接等于人工总时长，虚高 54%）。
2. **`slack` 默认 15**：Pareto 前沿在 ε≥15 饱和（总时长 72.5 / 出锅差 2.75 / 手动 32.8）。
3. **目标位权必须动态算**：`W_T = A_cold+1`，`W_Γ = W_T*(H+1)+A_cold+1`，`A_cold = 60000*H*|D|`。常数权重会在大实例上被冷等待项反超，字典序失效。
4. **目标三层优先级：原始跨度 Γ ≫ 总时长 T ≫ 语义冷等待**。语义只能兜底，不许拿评分项去换（放错顺序实测多输 2 个实例）。
5. 温度推断：同菜同设备众数 → 蒸箱默认 100℃ → 烤箱留空（保守独占一炉）。
6. 新增探针脚本：`scripts/gap_probe.py`（搜索/容量/输入精度）、`scripts/gap_probe2.py`（逐例对比）、`scripts/verify_model.py`（健全性自检）。

## 第二轮：程序层（接口/工程）加固 + 第三轨接入

### A. 接入第三轨（本轮最大收益）
`engine.schedule()` 从"贪心 + CP-SAT 双轨"扩成**三轨**，按 `(出锅差, 总时长)` 字典序取最优：
```
greedy = _schedule(...)
best = greedy
if use_cpsat and not hard_frozen:  best = cpsat(...) 若更优
if use_exact (默认跟随 use_cpsat, 可用 FT_EXACT=off 关):
    ex = model.solve_exact(..., fixed={k: st.start_min}, allow_preprocess=跟随策略)
    若 (gap, mk) 更优 -> best = ex
return _add_kitchen_semantics(best)
```
**关键点**：
- CP-SAT 轨**不支持冻结**，有 `hard_frozen` 时跳过；精确轨**支持 `fixed`**，所以重排也能受益。
- `use_exact` 默认跟随 `use_cpsat` —— `_eval_strategy` 用 `use_cpsat=False` 做毫秒级策略评估，
  绝不能让精确轨跑在那里（会把策略评估拖慢 5 倍）。
- 精确轨的 `allow_preprocess` **默认跟随策略**（不是无条件 True），保证与竞争的贪心解同任务集。
  `FT_EXACT_PREP=on` 可强制 True（备菜不计入总耗时），总时长再 −4.3pp 但出锅差退到 2.75 ⇒ **口径决策，需项目方拍板**。
- orchestrator 精解调用要传 `exact_budget=min(1.5, left)`，否则 1.5s 叠加 CP-SAT 的 1.2s 会破 5s 线。

**实测（60 组 seed=11，`FT_EXACT=off/on` 同口径对照）**：
| 配置 | 总时长 | 出锅差 | 连续手动 | 耗时 |
|---|---|---|---|---|
| 关第三轨 | 101.8 | 3.30 | 52.2 | 80 ms |
| **开第三轨（默认）** | **87.3** | **2.62** | **43.6** | **124 ms** |
| 上限参考(solve_with_gap 3s) | 76.8 | 2.60 | 33.7 | 47 ms |

净收益 **−14.2% / −20.7% / −16.5%**，逐例 **30优/30平/0负**。
端到端 `/api/plan` 4 道菜 **139 ms**（优秀线 5000 ms，余量 36×）。

### H. A13：动态重排被漏在三轨之外（出锅差 47 → 1）

`/reschedule` **端点**走 `agent_run()` → `engine.schedule()`，吃到了三轨；
但 `engine.reschedule()` **函数**仍直接调纯贪心的 `_schedule()` ⇒ 动态重排只有一条腿。
更隐蔽的是它默认 `priors=None`：**语义先验决定"哪些切配/腌制算备菜"**，
没有先验时 `prep_keys` 只认"超长冷藏/浸泡"硬判据 ⇒ 被冻结在 t=0 的步骤
因为"前置还在 t>0"让精确模型**直接判不可行（返回 None）** ⇒ 精确轨静默失效。

修法三条：
1. `reschedule()` 委托 `schedule(..., hard_frozen=...)`，自动复用三轨（CP-SAT 轨自动跳过，精确轨用 `fixed`）。
2. `priors is None` 时主动 `get_priors()`（与端点一致）。
3. 新增**冻结完整性校验**：精确轨的备菜变体是把备菜步**整步删掉**（不是挪到 t<0），
   所以候选解必须满足 `frozen_keys ⊆ 计划任务键`，否则否决 —— 防止"已完成步骤"凭空消失。

实测（2 菜 + 3 个冻结步骤）：**总时长 71.0 → 67.0，出锅差 47.0 → 1.0**，冻结步骤零丢失零挪动。
