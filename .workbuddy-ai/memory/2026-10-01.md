## Turn J：用户反馈"为何一直在加载中" → 新增 P-05（前端失败态）

### 一、用户看到的

打开 `index.html` 后，左侧「选择菜品」列表**永远停在「加载中...」**，右上角徽标「○ 状态未知」，
页面不报错、也不提示该做什么。

### 二、根因（不是后端故障，是前端缺失败态）

| # | 事实 | 位置 |
|---|---|---|
| 1 | 页面是**薄客户端**：菜谱/设备/档案/排程全部来自 FastAPI（18 处 `fetch('/api/…')`） | `index.html` |
| 2 | 正确入口是 `http://127.0.0.1:8137/app`（`start.bat` 自动打开）；`/` 重定向到 `/docs` | `main.py:888`、`start.bat:167` |
| 3 | **两种必然失败的打开方式**：① 双击 `index.html`（`file://`）⇒ `/api/*` 解析成 `file:///api/*`；② 静态预览/静态服务器 ⇒ 有 HTML 没后端 | — |
| 4 | `loadRecipes()` 的 `await fetch` **没有 try/catch** ⇒ reject 后占位符永远停在「加载中...」 | 原 `loadRecipes()` |
| 5 | `refreshLlmStatus()` 的 catch 写的是含糊的「状态未知」——把"连不上"说成了"不知道" | 原 `refreshLlmStatus()` |
| 6 | `loadLib/loadDetail/loadDevices/loadProf/loadHist` 同病 ⇒ 每个视图各自可能"永远转圈" | 同上 |

**关键判据：`fetch` reject 与 HTTP 4xx 是两件事。** reject = 后端不可达；
4xx/5xx = 后端**是活的**，只是这次请求有问题。混为一谈会把 P-03 的 403
「写入已在服务端关闭」盖成"连不上后端"，用户永远看不到真实原因。

### 三、修法

- 新增统一出口 `apiFetch(url,opts)`：**全文件只允许 1 处 `fetch(`**，就在它内部。
  漏一处就会出现"某个视图永远转圈"，且只在那个视图复现 —— 用 `re.finditer(r"\bfetch\(")` 计数锁死。

   900ms 收到 700ms。

### 关键设计发现

1. **中间件顺序**：Starlette `add_middleware` 是"**后加的更外层**" ⇒ 必须**先**注册 `_security_guard`（`@app.middleware("http")`）、**后**注册 `CORSMiddleware`，CORS 才在最外层，401/429 响应才带跨域头。实测 `[x.cls.__name__ for x in app.user_middleware] == ['CORSMiddleware','BaseHTTPMiddleware']`。
2. **测试必须 `importlib.reload`**：安全配置在**模块导入时**读取，只改 `os.environ` 不生效。`_load(monkeypatch, **env)` 用 reload 在指定环境下重载模块；请求直接喂 ASGI scope，不走真实网络（仓库不依赖 httpx）。
3. **`ortools` 直接依赖 `pandas`**（`pip show` 证实）⇒ `pandas`/`numpy`/`python-dateutil`/`six`/`tzdata` 全是它的传递依赖，`PyYAML`/`python-dotenv`/`httptools`/`watchfiles`/`websockets` 来自 `uvicorn[standard]`。**整个 freeze 没有杂包**，可整体作锁文件。
4. **`_parse_dotenv` 的合并顺序**：`.env` → `.env.local`（后者覆盖前者），且 `k not in os.environ` 保证**真实环境变量永远优先**（容器注入的凭据不会被仓库文件盖掉）。

### 护栏自身的三类事故（比缺护栏更危险）

1. **假阳性**：新写的 401 护栏用 `body.index("401")` 定位，命中的却是源码里那条「这里**不能**调 markBackendDown」的**注释** ⇒ 真代码对却报红。修法：加 `_strip_js_comments()`，所有 `assert "xxx" not in body` 一律比去注释后的代码。
2. **护栏互相打架**：变异串写成 `sk-hardcoded-please-do-not`，被 `test_no_credentials_hardcoded_in_source`（它扫 `scripts/`）扫出来 ⇒ 变异套件还没跑就先红一条。修法：变异串刻意不用 `sk-` 形状。
3. **断言太脆**：`ui_probe.mjs` 的「菜谱库总数显示」原来是 `/\d+道/` —— 新文案「共 2000 道 · 显示前 120」数字与「道」之间多了空格，正则不匹配 ⇒ 探针报 `120 通过 / 1 失败`。修法不是把空格加回去（那还是脆的），而是换成**语义断言**：解析出总数与「显示前 N」，并要求 N **等于真实渲染的行数**。同时补一条运行时检查「详情取不到时给明确结论（不是一整屏 undefined）」—— 静态护栏只能证明代码里写了 404 分支，只有真跑一遍才能证明它真的渲染出了那句话。
4. **新增代码让既有变异锚点失效**：`markAuthRequired()` 里也有一句 `bar.classList.add('on');`，使旧变异「横幅不再显示」的锚点从 1 次变 2 次 ⇒ 套件打 `[跳过]`（= 那条护栏已经没人验了）。修法：锚点带上前一行 `if(t)t.innerHTML=backendHintHtml();`。**这个坑只有跑完整套件才能发现** —— 单跑目标测试是看不出来的。

### ⚠ 记忆文件上限：10,000 字符（不是字节）

`MEMORY.md` 被截断注入的**真实阈值**在 `app.asar` 里：
```js
var MAX_MEMORY_CHARS = 1e4;
... content.substring(0, MAX_MEMORY_CHARS) + "... (memory truncated — MEMORY.md is too large)"
```
**按 JS 字符串长度算**（中文 1 字 = 1 字符但 3 字节）⇒ **按字节估会严重误判**：
14,188 字节 = 8,490 字符（安全），而 17,003 字节 ≈ 10,200 字符（超限）。
本轮先按字节砍了三轮都没到位（18,241 → 15,296 → 14,766 → 14,248），
最后按字符量才知道早就安全了。**结论已写进 `MEMORY.md` 文件头**。
